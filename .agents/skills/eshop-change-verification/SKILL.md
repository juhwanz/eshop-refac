# Eshop 변경 검증

`AGENTS.md`의 도메인 불변조건과 권한 범위를 먼저 따른다.

## 검증 루프

1. `git status --short`와 관련 운영 코드·테스트를 확인하고 사용자 변경을 구분한다.
2. 요청을 충족하는 가장 작은 변경을 구현한다.
3. 가장 가까운 테스트를 먼저 실행한다.
4. 현재 변경 때문에 실패했다면 원인을 수정하고 같은 검증을 다시 실행한다.
5. 가까운 테스트가 통과하면 위험도에 맞는 상위 검증으로 넓힌다.
6. `git diff --check`와 최종 diff를 확인하고 실행 결과와 남은 위험을 보고한다.

반복은 검증이 통과하거나 아래 중단 조건을 만날 때 끝낸다. assertion 약화, 임의 sleep 추가, 동시성 축소로 실패를 숨기지 않는다.

## 테스트 선택

- 빠른 기본 검증: `./gradlew unitTest`
- 안전한 전체 변경 검증: `./gradlew verifyChange`
- Redis 통합·동시성 검증: Redis를 준비한 뒤 `./gradlew integrationTest`
- 로컬 DB 변경·대량 데이터 검증: 사용자가 승인한 경우에만 `./gradlew stressTest -PallowStressTest`

변경 지점에 해당하는 테스트 클래스가 분명하면 `--tests`로 먼저 좁혀 실행한다.

## 중단 조건

- Redis나 MySQL 같은 외부 서비스가 없고 안전하게 준비할 권한이 없다.
- 스트레스 테스트나 데이터 초기화가 사용자 데이터를 변경할 수 있는데 승인받지 않았다.
- 실패가 기존 사용자 변경이나 요청 범위 밖의 문제에서 발생했다.
- 수정 방향에 제품·도메인 의사결정이 필요하다.

중단할 때는 실패 명령, 핵심 오류, 완료된 안전 검증, 다음에 필요한 조치를 구분해 보고한다.
