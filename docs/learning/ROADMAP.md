# E-Shop 학습 로드맵

프로젝트에서 실제로 사용한 기술을 중심축으로 삼고 답변에 필요한 Java/Spring와 CS 원리를 교차해서 학습한다. 상태와 복습 일정은 [`README.md`](README.md), 세부 범위는 [`COVERAGE.md`](COVERAGE.md)를 기준으로 한다.

## 운영 원칙

- 사용자 지정 주제와 복습 기한을 가장 먼저 따른다.
- 신규 학습은 최근 10개 기준 프로젝트 약 60%, Java/Spring·CS 약 40%를 지향한다.
- 한 역량을 넓게 읽는 대신 질문, 압박 질문과 30초 답변으로 설명 가능 여부를 확인한다.
- 프로젝트의 사실은 코드·테스트·ADR·설계 문서에서 확인하고, 일반 이론·실험·운영 보장을 구분한다.
- 복습은 기본적으로 최초 학습 다음 날, 3일 뒤, 7일 뒤에 배치하되 답변 수준과 면접 일정에 맞춰 조정한다.

단계는 선수 지식을 고려한 권장 순서일 뿐이다. 앞 단계를 전부 완료해야 다음 단계로 넘어가는 잠금 장치로 사용하지 않는다.

## 0단계: 범위와 답변 기준

1. `P01` 프로젝트 범위와 비즈니스 불변조건
2. `P17` 근거·대안·한계를 포함한 면접 답변 구조
3. `F01` 객체지향, 다형성과 불변 객체

목표: 현재 구현을 결제·정산·운영 서비스로 과장하지 않고, 기능보다 해결한 문제와 지킨 조건을 먼저 설명한다.

## 1단계: 요청 흐름과 Spring

1. `P02` 주문 요청과 시스템 전체 흐름
2. `F05` IoC/DI와 Bean 생명주기
3. `F06` Spring Boot 자동 설정과 외부 설정
4. `F07` MVC, AOP와 웹 경계
5. `P03` Spring 트랜잭션과 프록시 경계

목표: 요청이 애플리케이션에 들어와 트랜잭션을 거쳐 응답되는 과정을 프레임워크 원리와 연결한다.

## 2단계: 동시성, 트랜잭션과 취소

1. `F08` 프로세스·스레드·동기화와 deadlock
2. `F11` ACID·격리 수준·MVCC와 DB deadlock
3. `P04` 재고 동시성과 락 대안
4. `P05` Redisson 락의 실패 경계
5. `P08` 주문 취소와 재고 복구
6. `F04` Java Memory Model과 동시성 도구

목표: “Redis가 빠르기 때문” 같은 단순화 대신 각 동시성 제어가 보호하는 상태와 남은 실패 모드를 설명한다.

## 3단계: 멱등성, 대기열과 네트워크

1. `F10` TCP·HTTP, 웹 상태와 DNS·TLS·proxy
2. `P06` HTTP·Redis·DB를 잇는 주문 멱등성
3. `F13` Queue·Set·Hash table·Tree와 복잡도
4. `P07` Redis Lua와 상품별 admission queue

목표: timeout, retry, Redis 장애, TTL 만료, 동시 중복과 다른 payload 재사용을 포함한 실패 시나리오를 설명한다.

## 4단계: JPA, 데이터베이스와 조회

1. `F02` Collection, equals/hashCode와 예외
2. `F12` SQL·정규화·제약·인덱스와 실행 계획
3. `P09` JPA 영속성 컨텍스트와 조회 전략
4. `P10` No-Offset pagination과 인덱스
5. `P11` 스키마 제약과 마이그레이션 경계

목표: JPA 편의 기능이 만드는 SQL과 스키마 적용 범위를 데이터베이스 원리로 설명한다.

## 5단계: 캐시, JVM과 성능

1. `P12` cache-aside와 커밋 이후 무효화
2. `F03` JVM 메모리 구조와 GC
3. `F09` 가상 메모리와 blocking·async
4. `P15` 성능 지표와 k6 결과 해석

목표: 캐시의 정합성 경계와 성능 수치를 실행 환경·workload·불변조건에 연결해서 설명한다.

## 6단계: 보안, 검증과 운영

1. `P13` 인증·인가, JWT와 로그인 보안
2. `P14` 테스트 전략과 동시성 검증
3. `P16` CI·배포 경계와 관측성

목표: 정상 흐름뿐 아니라 인증·외부 의존성 실패, 테스트의 증명 범위와 실제 운영 자동화의 경계를 설명한다.

## 통합 연습

- 프로젝트 30초 소개와 핵심 사례의 2분 답변
- 동시성, 멱등성, JPA 성능, Redis 장애 troubleshooting
- 프로젝트 중심 모의 면접과 Java/Spring·CS 혼합 면접
- 틀린 질문과 자신감이 낮은 역량만 다시 보는 압박 면접

목표: 자료 없이 답하고 모르는 범위를 인정하며, 후속 질문에 코드 근거와 trade-off로 대응한다.
