# 면접 답변 구조

- 분류: 면접
- 관련 역량 ID: P17

기술 이름을 나열하기보다 의사결정과 검증 범위를 전달하기 위한 기본 구조다.

## 여섯 단계

1. **문제:** 어떤 사용자·시스템 문제가 있었는가?
2. **불변조건:** 어떤 조건은 실패 상황에도 지켜야 하는가?
3. **대안:** 현실적으로 검토한 선택지는 무엇인가?
4. **선택:** 어떤 기준으로 현재 방식을 골랐는가?
5. **검증:** 어떤 코드·테스트·실험이 주장을 뒷받침하는가?
6. **한계:** 무엇은 아직 보장하지 못하며 어떤 조건에서 재검토하는가?

모든 질문에 여섯 단계를 억지로 붙이지 않는다. 정의 질문은 짧게 답하고, 프로젝트 의사결정이나 장애 질문에서 이 구조를 사용한다.

## 모르는 질문에 답하는 방법

1. 모르는 범위를 정확히 밝힌다.
2. 알고 있는 인접 개념과 혼동하지 않는다.
3. 확인할 코드, 로그, 실행 계획, metric 또는 공식 문서를 제시한다.
4. 추측이 필요하면 추측임을 표시하고 검증 방법을 말한다.

## 자기 점검

- 결론을 첫 문장에 말했는가?
- 프로젝트에서 실제로 사용하지 않은 기술을 경험처럼 말하지 않았는가?
- 성능 수치의 환경과 조건을 설명했는가?
- 성공 흐름만이 아니라 실패 경계를 말했는가?
- 선택하지 않은 대안의 장점도 공정하게 설명했는가?

## 연습할 질문

1. 왜 DB 비관적 락 대신 Redis 분산 락을 선택했나요?
2. Redis SET NX만으로 주문 멱등성을 보장할 수 있나요?
3. No-Offset pagination이면 항상 빠른가요?

실제 30초·2분 답변은 사용자의 학습 세션 이후 해당 주제 문서에 기록한다.
