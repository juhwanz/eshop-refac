# 운영 자격 증명은 환경변수와 최소 권한 계정으로 관리한다

- 상태: 채택
- 날짜: 2026-09-04

## 배경

과거 저장소 이력에 DB 비밀번호, JWT 관련 값과 access token이 포함된 정황이 있다. 현재 파일에서 값을 제거하는 것만으로는 이미 복제된 자격 증명을 무효화할 수 없고, 관리자 DB 계정을 애플리케이션에서 직접 사용하면 유출 시 영향 범위가 커진다.

## 결정

- 운영 자격 증명은 Git에 저장하지 않고 환경변수와 GitHub Actions secret으로 주입한다.
- 운영 DB는 관리자 계정 대신 애플리케이션 전용 최소 권한 계정을 사용한다.
- JWT 서명키 유출 시 새 키를 배포하고 기존 refresh token을 제거해 전 사용자 재인증을 수행한다.
- 유출 대응은 자격 증명 폐기·교체를 먼저 수행하고 그 뒤 Git 이력을 정리한다.
- GitHub secret scanning, push protection과 CI Gitleaks 검사를 함께 사용한다.

## 검토한 대안

- 기존 관리자 DB 계정의 비밀번호만 교체: 변경은 작지만 다음 유출의 영향 범위가 계속 크다.
- 구·신 JWT 키를 동시에 허용하는 점진적 교체: 사용자 세션을 유지할 수 있지만 유출된 키의 유효 기간이 늘어나므로 P0 대응에는 적합하지 않다.
- GitHub secret scanning만 사용: 알려진 provider token 탐지에는 유용하지만 사용자 정의 JWT·DB 비밀번호를 모두 탐지하지 못한다.

## 결과

- 자격 증명 유출 시 권한과 피해 범위가 줄어든다.
- JWT 키 교체 시 사용자가 다시 로그인해야 한다.
- DB 계정 생성·회수와 배포 secret 교체를 운영 절차로 관리해야 한다.
- Git 이력 재작성 후 기존 clone과 브랜치를 재사용하지 않아야 한다.
